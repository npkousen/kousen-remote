Linux Bluetooth remote input service

Turn a Siri Remote into normal Linux keyboard and media input.

Kousen Remote is a standalone service for kiosk and media systems. It listens to Bluetooth reports from an Apple Siri Remote, normalizes the button actions, and emits regular Linux input events through uinput so Chromium, KousenTV, VLC, Plex, and other apps can respond without Apple-specific code.

What This Project Does

Kousen Remote keeps remote-control support below the application layer. Browser apps and media players receive standard Linux input instead of depending on Bluetooth implementation details.

Target

Apple Siri Remote 3 USB-C

The initial hardware profile targets the Apple Siri Remote third generation USB-C model on Debian through BlueZ.

Runtime

Standalone Linux service

The service can run by hand for testing or under systemd for kiosk startup and reconnect behavior.

Boundary

No app integration required

KousenTV, CommandCenter, Chromium, and VLC should see ordinary key events and stay free of Apple Bluetooth code.

Requirements

The first release is intentionally Linux-focused because it depends on BlueZ, D-Bus, and the Linux uinput input subsystem.

Recommended host

  • Debian stable or Ubuntu Server LTS
  • Bluetooth controller managed by BlueZ
  • Python 3.9 or newer
  • Administrative access for pairing and uinput service installation

Linux packages

The systemd installer installs python3-venv, python3-pip, python3-dbus-next, python3-evdev, and bluez when they are missing.

Step-by-step Install

Start in print-only mode first. It confirms pairing, GATT notifications, report decoding, and action mapping before the service injects real input into Linux.

Install the repository on the Linux host

Clone the public repo and create a virtual environment for local testing.

sudo apt-get update
sudo apt-get install -y git python3-venv bluez
git clone https://github.com/npkousen/kousen-remote.git
cd kousen-remote
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .

Scan for compatible remotes

Put the Siri Remote in pairing mode, then scan for likely compatible devices.

kousen-remote scan --seconds 10

If BlueZ hides useful advertisement data during filtered scans, scan more broadly.

kousen-remote scan --seconds 10 --no-hid-filter --all

Pair, trust, and connect

Use the Bluetooth address reported by the scan or by kousen-remote devices --all.

kousen-remote pair XX:XX:XX:XX:XX:XX
kousen-remote info XX:XX:XX:XX:XX:XX

Inspect GATT reports if needed

The default runtime listens to char0038, the observed button report characteristic for the initial Siri Remote profile.

kousen-remote gatt XX:XX:XX:XX:XX:XX
kousen-remote gatt-notify XX:XX:XX:XX:XX:XX char0038

Run print-only validation

This mode prints decoded actions without injecting keyboard events.

kousen-remote run --output print --mapping mappings/kiosk-browser.json XX:XX:XX:XX:XX:XX

Run with uinput output

After print-only output looks correct, run the service path with Linux uinput so applications receive normal key events.

sudo .venv/bin/kousen-remote run --mapping mappings/kiosk-browser.json XX:XX:XX:XX:XX:XX

Install The systemd Service

For a kiosk or media appliance, install Kousen Remote under systemd after the remote has been paired and validated.

Install and start

sudo packaging/systemd/install-systemd.sh --device XX:XX:XX:XX:XX:XX

The installer copies the project to /opt/kousen-remote, writes /etc/default/kousen-remote, installs the unit file, enables the service, and starts it.

Install without starting

sudo packaging/systemd/install-systemd.sh --device XX:XX:XX:XX:XX:XX --no-start

Use this when you want to review the environment file before the service starts injecting input.

Inspect the service

systemctl status kousen-remote.service
journalctl -u kousen-remote.service -f
cat /etc/default/kousen-remote

Control the service

sudo systemctl restart kousen-remote.service
sudo systemctl stop kousen-remote.service
sudo systemctl disable kousen-remote.service

Troubleshooting

Most setup issues are either Bluetooth pairing state, permissions, or a sleeping remote that needs to wake before the service can subscribe to notifications.

No candidate appears during scan

Try --no-hid-filter --all, wake the remote, restart Bluetooth, and confirm the host adapter is visible to BlueZ.

GATT objects are empty

Confirm the remote is connected. Some remotes expose useful GATT data only after a fresh connection or wake event.

Print-only works but uinput fails

Run the uinput path with sudo or review permissions for /dev/uinput. The systemd service is installed to run with the needed privileges.

Input repeats after disconnect

The runtime releases the active key when the remote becomes unavailable and retries connection with backoff. Check the service journal for reconnect messages.

Public repo note: keep Bluetooth addresses, hostnames, SSH keys, tokens, private LAN notes, and device-specific recovery details out of public issues, screenshots, and committed config files when they identify your private setup.
